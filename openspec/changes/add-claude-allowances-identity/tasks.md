`feat/claude-allowances-identity`. The coordinator owns `tasks.md`,
`evidence.md`, the delta specs and AGENTS.md. Stage explicit paths only. Use
atomic, signed Conventional Commits with no attribution trailers. Use synthetic
fixtures only: no private transcripts, ids, emails, paths, provider-state or
settings values. No test or implementation step reads or writes the real
`~/.claude`, `~/.claude.json` or `~/.claude/settings.json`; tests use temporary

`claude` CLI except in task 5.3 as stated, never read the credential file and
never call the OAuth usage endpoint, `claude auth status` or `/usage`. Run every
`openspec` command with `OPENSPEC_TELEMETRY=0`. Every new test must
fail on `7a9fefb`; regression guards are existing tests only and must pass on
both `7a9fefb` and the change (design D11). A new no-change assertion sits in
a test that also asserts new behaviour; a test of a not-fresh case asserts a
following fresh tail so it fails there too; a fixture whose configuration
holds a Claude mapping and asserts an absence or a rejection also asserts
something that needs the new configuration accepted (exit 0, a Codex or
Claude row or email present), and each rejection is paired with an accepted
neighbour in the same test. Commit order across lanes: 1.3 before 2.1, 3.1
only after 2.1, and 3.3 only after 3.1, so no commit pairs a seven- or
ten-value mod with the four-value parser (design D10) and no implementation

in the design, specs and these tasks. Implementation may start.
