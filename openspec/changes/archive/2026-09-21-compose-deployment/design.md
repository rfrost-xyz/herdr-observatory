# Design

A Python slim image contains all application code and OpenSSH client. Compose uses host networking to preserve loopback-only HTTP and kernel network telemetry, matching source UID for socket access, read-only root, dropped capabilities, a private temporary filesystem and bounded logs. The Python image is pinned by digest; application images are tagged with reviewed Git revision. No source checkout is mounted.

Local collection sends only session.snapshot to an explicitly configured Unix socket with timeout and bounded response, using the existing allowlist. Mount the containing Herdr directory read-only so socket replacement recovers; this socket still conveys Herdr authority at the OS level, so the fixed request and lack of mutation endpoints are the application boundary. Theme and disk paths are explicit: mount only the active-theme parent, and measure the filesystem containing the socket directory. The receiver mounts a dedicated feed directory writable; other mounts are read-only. Remote collection retains the existing read-only SSH probe.

Personal Compose mounts a dedicated SSH configuration and pinned known-host file, not the whole SSH directory or Docker socket. Tailscale SSH uses the existing host network route. Publication executes the receiver module inside its named container over authenticated SSH, removing the remote release-directory dependency. The SSH account already controls Docker; no Docker socket enters Observatory. Deployment configuration lives outside Git and outside development worktrees. Work uses named-volume subpaths because its SSH shell and Docker daemon have different filesystem roots.

Migration stages and verifies a new image on an alternate loopback port, then replaces only the dashboard service. Keep previous config and image for rollback. Enable Docker boot startup on the laptop if required; do not restart unrelated workloads. Verify profile boundaries, live agents, theme and publication, service restarts, narrow mounts and absence of the old transient service.
